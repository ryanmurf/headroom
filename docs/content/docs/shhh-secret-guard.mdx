title: "Proposal: shhh secret masking at request ingress"
description: "Measured scanner feasibility and the enforcement work still required in this fork. Not an enabled runtime feature."
---

This fork pairs Headroom with [ryanmurf/shhh](https://github.com/ryanmurf/shhh),
a session-secret scanner. A prototype in shhh's `feat/inline-secret-masking`
branch demonstrates in-memory text masking. **This page is a design proposal;
no live traffic is protected by it and no runtime guard is installed.**

## Why the ordinary extension hook is insufficient

Source inspected at Headroom commit `5023c84e527e28281dd73d1ba04184fe738aac0f`:

- `headroom/pipeline.py`: `PipelineExtensionManager.emit` catches exceptions,
  logs them, and continues. Discovery failures also skip the extension. This is
  appropriate for optional transforms, but a scanner failure must not forward
  the original request.
- `headroom/proxy/handlers/anthropic.py`: `INPUT_RECEIVED` exposes messages and
  tools rather than the entire request. Top-level system context needs explicit
  coverage, and some passthrough paths precede this event.
- `headroom/proxy/handlers/openai.py`: the large-body passthrough path can return
  before `INPUT_RECEIVED`. Blocking or disabling compression must not bypass
  secret enforcement.
- `crates/headroom-proxy/src/main.rs`: the Rust front proxy can intercept
  requests itself. A Python-only extension does not establish coverage of every
  path through that proxy.

The security boundary must therefore be an explicit ingress guard, earlier than
request-body logging, cache writes, memory extraction, compression, and every
upstream forwarding path. A second `PRE_SEND` scan cannot undo earlier storage.

## Scanner feasibility

The shhh prototype reuses the existing named patterns, adds provider-key and
credential-assignment coverage, and replaces exact merged spans. It removes
entire private keys, preserves assignment syntax, and reports type/count metadata
without value prefixes, suffixes, excerpts, or raw-value caches. It avoids offline
report construction, repeated line-position scans, entropy analysis, and process
startup per request. It also exposes a helper for parsed JSON string values.

Measured on Tron with Node v24.15.0, Linux x64, 25 samples after 3 warmups, no
scanner cache, entirely synthetic decoded tool-output text:

| Input | Secret occurrences | Scan + mask median / p95 | JSON parse + mask + serialize median / p95 |
|---|---:|---:|---:|
| 64 KiB | 8 | 0.154 / 0.238 ms | 0.215 / 0.291 ms |
| 1 MiB | 32 | 2.550 / 2.884 ms | 5.125 / 6.043 ms |
| 64 KiB | 800 | 0.624 / 0.804 ms | 0.330 / 0.367 ms |

The offline reporter took 26.526 ms median for the 1 MiB sparse case and
40.673 ms for the dense case. This compares different jobs and rule coverage;
it is not an accuracy-equivalent scanner speedup claim. Independent JIT-warmed
phases can have different timing distributions. The benchmark source and full
results live in shhh's `benchmarks/` directory. Proxy transport, IPC, concurrent
load, provider prompt-cache behavior, false-positive/negative rates, malformed
requests, and hostile-input costs are not included in those numbers.

These measurements support the feasibility of a small inline cost. They do not
establish a production latency bound or complete secret detection.

## Proposed enforcement contract

1. Decode bounded request bodies at the outermost forwarding boundary. Reject
   unsupported encoding, malformed JSON, oversized input, unsupported protected
   routes, and scanner timeout/failure with a generic error and no content dump.
   Do not fall back to forwarding the original request.
2. Cover Anthropic system/messages/tool descriptions; OpenAI Chat messages and
   tool definitions; Responses instructions/input/function arguments; and Gemini
   equivalents. Validate and preserve structural IDs, model names, signatures,
   cache metadata, opaque encrypted blocks, and image/audio data. Authentication
   headers remain transport credentials and are never passed through the content
   masker. Opaque blocks need a documented allow/deny policy rather than a false
   claim they were scanned. MCP traffic itself and non-model network access are
   outside this proxy boundary.
3. Scan decoded string values, including credential-named JSON values. Preserve
   exact non-secret bytes where possible; reserialize only changed bodies and
   update content-length. Scan history too: compression's live-zone-only policy
   must not be inherited by the secret guard. A cache may be considered only after
   profiling, with bounded sanitized values and keyed digests, never raw originals.
4. Run one long-lived bounded scanner worker per gateway worker rather than
   spawning a Node CLI per call. Measure IPC and queue latency; enforce a deadline
   outside the scanner process. A native Rust port with shared rule fixtures may
   later avoid IPC and provide a safer regex engine, but needs its own coverage
   and performance proof. Keep the prototype's JS regexes off an unbounded,
   synchronous security-critical request path.
5. Pass only sanitized content to Headroom's cache, logger, memory extraction,
   compressor, and upstream. Logs and metrics carry rule IDs, counts, duration,
   and generic failure codes only. Do not include scanner exception text if it
   could contain the input. Masking is deterministic; no raw-value restoration
   map is introduced by this proposal.

## Required integration proof before enabling

- Mock upstream and every cache/log sink: inject synthetic secrets into each
  provider shape and assert those strings appear in none of the sinks. Verify
  byte-faithful unchanged requests, Unicode, escaped JSON, nested function
  arguments, multiline PEMs, overlaps, repeated matches, and structured parts.
- Exercise compression off, cache on/off, large-body bypass, Rust interception,
  Python forwarding, replay/retrieval, count-token routes, alternate provider
  routes, malformed/oversized bodies, unsupported encodings, scanner crash,
  deadline expiry, saturation, and missing scanner configuration. No protected
  failure path may contact the upstream or cache/store original content.
- Define image, audio, encrypted content, WebSocket/realtime, streaming request
  bodies, encoded credentials, and secrets split across content blocks. The
  current prototype does not detect arbitrary encoded/unknown secrets, does not
  scan numeric JSON credentials, and does not join separate text blocks.
- Measure warmed and cold behavior, memory, IPC, throughput and p95/p99 latency
  under realistic concurrent session replay. Evaluate precision/recall on a
  representative labeled corpus before choosing broad credential/entropy rules.

The fork is not configured in any Claude or Codex profile. Existing RTK launchers
are unchanged. A model-traffic guard cannot stop direct exfiltration through
shell commands, Git, email, MCP tools, or other network-capable tools, and cannot
erase secrets already written by the agent to its local session transcript.
